# 独立导航页面设计

## 目标

将探索主界面上的底部导航按钮和数字人周围的功能按钮，从当前页面浮层切换改为真正的独立页面导航。每个页面拥有独立 URL，支持浏览器前进、后退和刷新恢复。

## 路由映射

| 路径            | 页面         | 入口                       |
| --------------- | ------------ | -------------------------- |
| `/`             | 探索主界面   | 底部“探索”                 |
| `/home`         | 智慧文旅首页 | 底部“首页”                 |
| `/guide`        | 对话导览     | 底部“导览”                 |
| `/narration`    | 实时讲解     | 舞台“实时讲解”             |
| `/map`          | 全景地图     | 舞台“全景地图”             |
| `/itinerary`    | 智能行程     | 底部“行程”、舞台“智能路线” |
| `/voice`        | 语音交互     | 舞台“语音交互”             |
| `/profile`      | 我的旅程     | 底部“我的”                 |
| `/lab/lip-sync` | 口型实验室   | 保留现有内部入口           |

未知路径回退到探索主界面。

## 页面结构

- 探索页保留现有数字人、左右全息侧栏和底部导航，不再渲染功能浮层。
- 其他路由渲染完整占屏的功能页面，沿用翠绿色、天青色和晨曦金色的全息视觉体系。
- 功能页提供返回探索按钮，并保留底部导航，使用户可以直接切换到其他独立页面。
- 页面内容复用现有景区数据、问答、路线、语音和地图交互，不复制业务状态。

## 导航行为

- 点击入口使用 History API 在当前标签页切换 URL。
- `popstate` 触发时重新解析当前路径，保证浏览器前进和后退可用。
- 刷新任意功能页时，由 Vite 的 SPA 回退加载应用，再按路径恢复页面。
- 页面切换后滚动位置回到顶部，并更新当前导航项的 `aria-current`。

## 交互规则

- 导览页的快捷问题提交后跳转到 `/`，在主界面对话区展示流式回答。
- 实时讲解页开始讲解后跳转到 `/`，由数字人继续播报。
- 地图页点击景点后跳转到 `/` 并发起对应路线提问。
- 语音页开始录音后跳转到 `/`，主界面继续显示识别和回答状态。
- 行程页和我的旅程页保持在各自页面，不使用覆盖探索页的弹层。

## 组件边界

- `routing/appRoute.ts`：路径与应用页面之间的纯函数映射。
- `RootApp.tsx`：监听浏览器导航并选择实验室或文旅应用。
- `App.tsx`：持有共享业务状态，根据路由渲染探索页或独立功能页。
- `components/TourismPage.tsx`：承载独立页面外壳和各页面内容。
- `components/TourismNav.tsx`：统一底部导航及其 URL 跳转行为。

## 错误和兼容处理

- 景区数据加载失败时，所有路由统一显示现有错误状态。
- 不引入额外路由依赖，避免改变现有构建和部署方式。
- 桌面端和移动端均不得出现横向溢出；功能页按钮满足键盘操作和清晰焦点状态。

## 验收标准

1. 所有标注按钮点击后地址栏变为对应路径，页面不再以浮层覆盖探索页。
2. 浏览器后退可返回上一页面，刷新后仍停留在当前功能页。
3. `/itinerary` 可由两个入口到达，且显示同一页面。
4. 功能页中的提问、讲解、地图和语音动作继续调用真实业务逻辑。
5. 桌面和 `390x844` 移动视口无横向溢出，底部导航可用。
6. 类型检查、组件测试、路由测试和浏览器点击回归通过。
